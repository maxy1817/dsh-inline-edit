# 实现与兼容性

核心行为以 DSH 0.2.1-rc.3 的公开契约为基准；0.3.0 在官方 rc.5 的隔离 Web/Host 中通过离线适配器验证，并完成真实 Host 重启恢复。浏览器人工验收范围以 VALIDATION.md 为准。开发依赖保留 rc.3 基线，设置模块固定 rc.5 以复现其读取失败行为；这不表示已验收 engines.dsh 范围内的所有版本。使用已发布 npm 包的公开接口，不修改 DSH 程序或会话文件。

0.3.0 兼容性修订保留生产代码与开发基线，使用显式预发布分段声明 0.2.1 与 0.2.2 的宿主及 dsh-llm peer 范围，并接受已验证的 schemastery 3.19.x。使用实际安装的 DSH 0.2.2-rc.1 依赖运行 114 项 Host 相关测试通过；这不等同于重新完成新版全部界面验收。

## 消息资格

history.js 从会话事件构建 dsh-inline-edit-latest 投影。首次进入 agent/inbox/spliced 时记录消息是空闲 next-turn 输入还是运行中补充，不因之后的出队或移到新轮次而重新分类。turn/start/end 与普通用户事件识别主消息；视图只传最新主消息序号及被排除消息序号。

前端对补充/steering 消息不显示当前模式编辑按钮，对旧主消息显示禁用说明。后端重新计算资格，不信任客户端分类。设置未加载完成时不使用默认分支方式误提交。

0.2.11 同时订阅原生 ConfigForm 与 configForms.describe() 的共享 mirror。原生缓存表单在首次读取失败后仍为 loading，重复 get() 不会重新请求；设置页挂载时调用一次 ensure()，失败后通过显式重试恢复。共享 mirror 去重进行中的读取，不轮询。仅接受 ready 且 mode 明确为 branch/current 的配置；读取失败、命名空间不可用、解码或字段异常分别提示，不能通过去掉就绪检查来绕过保存的模式。

## 同会话提交

1. sessionController.resolveAgent() 恢复目标 Agent，要求空闲且队列为空。
2. runMaintenance() 独占维护阶段；核验尾序号、Agent 身份和目标消息仍在当前 surface。
3. 校验完整文本、原附件、新上传收据和图片能力。异步校验结束前不替换历史。
4. 同步追加 producer-owned user/message，source.kind=dsh-inline-edit，使用公开 surfaceOp: replace 与准确的 sourceEventSeqs，覆盖目标消息起的旧上下文。
5. agent.followup() 提交修改后的普通用户消息，提交上传绑定。会话 ID 不变。

编辑标记包含简短的模型可见上下文说明和恢复信息。非空 user-context 可兼容不接受空用户输入的模型服务，它不是伪造的系统提示词或助手回答。维护阶段不能追加 developer/message：V4 恢复校验要求它属于未关闭的 step，测试覆盖这一反例。

0.2.2 通过 replacement.id 与被编辑消息的 ID 精确追溯版本链。重复编辑时，仍在 surface 上的旧编辑标记也纳入替换，避免旧 replacement 文本留在适配器收到的 source 元数据中；同时合并界面隐藏范围。升级前积累的标记也能沿链处理。独立的后续任务不会误匹配前一轮编辑。分支模式沿同一版本链寻找原始 cutoff，并跳过原输入的队列入场事件。

请求 ID 去重仅作用于原 Session。进程中断后 agent/created 检查该 Session 的编辑标记；尚未进入持久队列的替换消息恢复一次。已经入队、提交或被明确取消的输入不重复发起。分支继承的标记不触发恢复。提交状态不确定时，客户端禁止直接再次发送，要求先刷新。

恢复和重试还要求标记仍在当前 surface，且之后没有新编辑或其他用户输入（包括入队后尚未消费的消息）。用户已开始新任务时，不再补发过时的编辑请求。

## 显示与审计

提示框基于固定版本的 DSH MIT Tooltip 源码，src/vendor/dsh-tooltip.js/.css 保留原有显示、悬停、键盘、点击固定和关闭交互。0.2.8 改为贴近锚点的上下左右定位：短提示优先按钮正下方居中，长编辑限制说明优先下方右对齐，间距统一 8px；不再整体避让到时间行左侧或对角换位。独立定位函数先在横向视口边缘夹紧，再按首选、反向、垂直侧尝试，只避让当前消息区域的交互控件，避免其他轮次工具栏导致跳位。拥挤时选择遮挡最少的位置并保持可见；未固定的提示不拦截指针事件。scripts/sync-tooltip.mjs 从固定依赖重建适配文件，不修改宿主。

message-time.js 独立实现原生本地日期格式；原生日期函数没有公共导出。客户端在下一本地午夜更新参考日期，卸载时清除定时器。时间文字不换行，沿用宿主次级文字字号。0.2.9 增加完整本地日期与秒的悬停/键盘提示，time 元素可聚焦并保留语义化 dateTime 与完整无障碍标签。复制操作先发起剪贴板写入，再仅对指针点击释放按钮焦点；异步结果不会再次改变焦点。

0.2.10 按正文是否含非空白字符决定复制按钮的显示，复制时仍传递完整原文。编辑器的原图片通过宿主传入的 loadImage(ref) 获取会话缓存 URL，其所有权属于宿主，附件卡不撤销这些 URL；新图片使用本地 File 创建对象 URL，在移除、取消或卸载时撤销自身创建的 URL。组件通过存活标记及附件、加载器身份忽略迟到结果，避免旧预览覆盖新来源。读取失败或图片解码失败时回退为文件图标，保留文件名和移除操作。

构建使用 esbuild 的 text 加载器内嵌 CSS。src/style.css 的换行字符也属于输出字符串的一部分，因此 .gitattributes 对该文件指定 eol=crlf，其他文本仍按 LF 检出。此规则维持已有源码与 lib/client.js 的可重复构建，不修改运行逻辑。不要在没有重建 lib 的情况下删除这条规则或调整 CSS 换行。

日志保留旧内容；模型上下文由 native surface 决定。dsh-inline-edit-history 投影记录被替换范围，Client 通过公开 slots 委托原生 ChatFlow，过滤旧节点和分组。保留宿主 React 与原生组件；自有子槽位递归镜像公开渲染契约，避免重声明原生子槽位所有权。

轨迹和用量统计不删减。原生轮次导航尚未按替换范围过滤，可能指向不再显示的旧轮次。这是界面限制，不影响会话 ID、模型上下文或持久化恢复。

停用插件后原生 transcript 可能重显旧审计内容；核心 surface 替换仍生效。不能把该功能描述为物理删除或隐私擦除。

## 编辑布局与图片预览

0.2.14 引入宿主公开 ReferenceChip 蓝色文件名和原子路径引用。消息正文中的文件引用由 ctx.uiConversation.userText.createEvaluator() 按宿主规则识别，collectFileReferences 保留 UTF-16 范围和元数据，缺少规则或规则异常时回退为文本，不添加自有正则猜测。

0.3.0 让普通文件附件和已识别路径引用共同进入独立 Lexical 0.49.0 编辑实例。ReferenceChipNode 和单换行文本投影适配自固定版 DSH。普通附件节点仅保存可信附件键，正文投影不包含文件标签或虚构路径；原附件引用与新 File 对象由编辑器生命周期内的可信注册表保留，选择、删除、剪切、撤销和重做同步实际附件列表。标签无额外删除按钮。路径引用节点则以原始 clipboardText 参与提交、复制和剪切，显示名不替代原始文本。

文件选择、粘贴和拖入在保存的选区插入原子节点，选择器抢走 DOM 焦点后仍恢复原位置；从 textarea 首次添加普通文件时迁移其 UTF-16 光标位置。插入后选区落在最后一个文件之后，可直接继续输入，文件前、中、后均可放置文字，不使用补空格作为光标占位。输入历史、选区和撤销由本插件实例管理，不绑定主输入框或宿主私有 session shell。同时没有普通文件和已识别路径引用的消息仍使用 textarea，图片保留独立预览行。富文本实例关闭时释放监听、历史引用、portal 与待执行帧。

0.2.13 通过宿主 primitives 的公开 ImageLightbox 直接使用 DSH 图片放大组件。其 props、实现与样式在已核对的 rc.3/rc.5 中一致；浮层 portal、遮罩关闭、Esc、焦点约束和恢复由原生组件负责，不另造预览器。预览沿用缩略图 URL，不复制或上传图片；附件或加载器改变时旧浮层关闭。

edit-scroll-anchor.js 在打开、取消、正文和附件变化前记录消息底边，在编辑区完成自动高度后一次性补偿最近的垂直滚动容器，剩余位移交给外层容器。原子标签 portal 首次挂载后另核对最终高度。按实际边界钳制；原生滚动已经补偿则不重复调整。事务遇到滚轮、触摸或滚动按键等用户操作时取消，完成或卸载时清理监听。不开启持续锁定，不改宿主 overflow-anchor，也不使用负外边距覆盖前文。无滚动空间时采用自然布局；窗口宽度变化仍由原有 ResizeObserver 更新高度。

## 运行边界

Host 仅在已认证 Connection 注册 plan/current/reuse-file 三个路由。附件索引由原消息确认；上传收据属于目标 Agent；客户端不能读取任意文件路径。请求体限量读取，错误返回短代码，不回传私有路径。

分支模式保持 native fork + prompt 链路。当前模式不调用 fork，不增加聊天，也不撤销执行过的命令和文件修改。

安装包使用宿主提供的 dsh-llm、schemastery、zod peer 依赖，不打包 DSH Host 或 React。上游 rc.3 的开发依赖固定了较旧的 zod，npm audit 会报告其集合校验资源耗尽公告；未强制升级宿主依赖。本项目直接开发依赖使用 zod 4.6.6。应随 DSH 升级重新验证，不执行 audit fix --force。
