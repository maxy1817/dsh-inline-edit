# dsh-inline-edit

DeepSeek Harness 原生消息编辑插件。点击消息旁的铅笔，在原位置修改文字、添加或移除附件；右下角为「取消」和「发送」。

## 重新生成方式

打开 **设置 → 消息编辑**。选项自动保存到当前 DSH profile；切换选项不会立即修改已有聊天。

| 方式 | 可编辑范围 | 结果 |
| --- | --- | --- |
| 增加分支（默认） | 支持的历史用户消息、已提交的普通用户插话 | 保留原聊天，从修改的位置另建聊天 |
| 在当前对话重新生成 | **最近一条在空闲时发送、发起任务的主消息** | 保持同一个会话 ID，侧边栏不增加聊天 |

**运行中插入或排队追加的补充消息不属于当前模式的可编辑范围。** 即使后来单独得到回答，也不会变成主消息。这些消息没有原地编辑按钮，后台同样拒绝提交；更早的主消息请使用分支模式。

修改主消息后，**它之后的补充消息和回答一并替换**，按修改后的内容重新生成。先等待任务完成或停止，并处理完待发送队列。DSH 自带的「编辑排队消息」属于未提交输入管理，不受本插件影响。

## 文字与附件

- 只改文字时保留原附件；只增删附件时文字可以不变。
- 支持文字与附件一起修改，也支持只有附件的消息。
- 多文件选择、拖入、粘贴；取消还原原内容。
- 移除附件**不删除电脑上的原文件**。
- Enter 换行，Ctrl/Cmd + Enter 发送，Esc 取消；中文输入法确认选字不会误发送。
- 未改动、提交中、不可编辑时禁用发送。失败保留草稿；提交状态不确定时要求先刷新检查，避免重复运行。

使用 DSH 原生 SVG、主题颜色、字体和圆角。设置支持深色及窄窗口；保存失败时保留服务器已经接受的选项。

信息图标沿用 **DSH 原生提示框的样式和交互**，只显示「在当前对话重新生成」或「在新分支重新生成」，不附带说明段落。优先位于图标右下方，水平与垂直间距均为 6px；空间不足时换角，尽量避开按钮和输入区域。支持悬停、键盘聚焦和点击；详细规则保留在设置页面。模式在打开编辑框时固定，之后的设置变更从下一次编辑生效。

消息操作区的编辑、复制提示优先放在按钮左侧，并让开同一行的时间和相邻按钮；没有合适空间时换位。四角均拥挤时仍显示提示，选择遮挡最少的位置，不保证完全不覆盖其他内容。点击不可编辑的铅笔不追加重复文字；提交失败和结果不确定的提示会保留。设置中的两个模式各有圆角边框，选中项高亮。

当前版本为 **0.2.5**。本版的自动检查结果与尚未覆盖的场景见 [验证记录](docs/VALIDATION.md)。

## 安装与升级

已验证：**DSH 0.2.1-rc.3，Windows 官方 Web 客户端与 Host**，使用桌面安装包自带 CLI。Electron 窗口专用传输、其他 DSH 版本和远程代理未单独验收。

在安装包目录执行：

~~~powershell
dsh plugin --profile desktop add "./dsh-inline-edit-0.2.5.tgz"
~~~

Web 配置把 desktop 改为 web。找不到 dsh 命令时，使用桌面安装目录下 resources/runtime/cli/bin/dsh.cmd 的完整路径。重新打开 DSH，在设置中选择模式。预构建包无需安装开发依赖。

升级可安装新包；如提示已存在，先在插件管理中卸载旧包，再安装。默认仍为分支模式，不会自动修改已有聊天。

~~~powershell
dsh plugin --profile desktop remove dsh-inline-edit
~~~

**尚未发布 npm 或市场。** 按包名安装和市场搜索，需要所有者实际发布并完成收录，见 [发布说明](docs/PUBLISHING.md)。

## 历史与边界

DSH 采用追加式日志。本插件使用公开 Session API 替换模型上下文，通过原生界面扩展过滤旧消息；**不改写或物理删除原日志**。旧内容可以在「轨迹」中审查，实际轮次和 Token 消耗继续保留。原生轮次导航仍以完整日志为准，可能包含已替换轮次。

停用插件后，原生聊天视图可能重显旧审计正文，但模型上下文仍采用已提交的替换；重新启用恢复过滤。不能将本功能视为隐私擦除。

**重新生成不会撤销已经执行的文件修改、命令、工具或外部操作。**

连续修改同一条消息时，旧版本的恢复记录也会退出活动上下文；从修改后的消息创建分支同样回退至其原始边界。编辑中断后如果已经出现新的用户输入，不再自动补发那次旧编辑。正常的更早对话继续保留。读取磁盘文件、轨迹或外部记忆的工具仍可能重新取得历史内容，本功能不清除这些外部状态。

其他限制：

- 已压缩且离开当前模型上下文的消息，不支持当前模式，请使用分支。
- 技能/会话引用、子智能体和非普通用户来源消息不重发，避免丢失语义。
- 最多 32 个附件；单个 64 MiB、合计 128 MiB、图片合计 20 MiB；仍受模型和 DSH 限制。
- 图片支持 PNG/JPEG/WebP/GIF；其他文件使用原生上传。文本最多 20 万字符。
- 草稿仅在内存，刷新、切换会话或关闭程序后不保证恢复。
- 同时替换聊天 Flow/消息槽位的第三方插件需额外兼容测试。

## 开发

以下命令仅适用于完整源码仓库，不适用于解压后的预构建分发包。需要 Node.js 24.9+：

~~~sh
npm ci
npm run check
npm pack
~~~

随源码提交预构建 lib/ 和 .gitattributes。后者保留 src/style.css 的 CRLF 换行，使文本加载器生成的 CSS 字符串在不同平台与现有构建包一致。React 与 Host API 使用宿主模块。无安装脚本，不全局安装、不修改 PATH。

Host 走 DSH 已认证的 Connection，不另开端口。附件只接受可信原消息引用或目标会话上传收据；不能提交任意磁盘路径。当前模式有空闲锁、尾序号检查、请求去重和中断恢复。模型收到简短编辑说明及新问题，不会收到被替换的旧问答。
