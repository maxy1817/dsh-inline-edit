# dsh-inline-edit

DeepSeek Harness 原生消息编辑插件。点击消息旁的铅笔，在原位置修改文字、添加或移除附件；右下角为「取消」和「发送」。

## 重新生成方式

打开 **设置 → 消息编辑**。选项自动保存到当前 DSH profile；切换选项不会立即修改已有聊天。

| 方式 | 可编辑范围 | 结果 |
| --- | --- | --- |
| 增加分支（默认） | 支持的历史用户消息、已提交的普通用户插话 | 保留原聊天，从修改的位置另建聊天 |
| 在当前对话重新生成 | **最近一条在空闲时发送、发起任务的主消息** | 保持同一个会话 ID，侧边栏不增加聊天 |

**运行中插入或排队追加的补充消息不属于当前模式的可编辑范围。** 即使后来单独得到回答，也不会变成主消息。这些消息没有原地编辑按钮，后台同样拒绝提交；更早的主消息请使用分支模式。

修改主消息后，**它之后的补充消息和回答一并替换**，按修改后的内容重新生成。先等待任务完成或停止，并处理完待发送队列。DSH 自带的「编辑排队消息」属于未提交输入管理，不受本插件影响。

## 文字与附件

- 只改文字时保留原附件；只增删附件时文字可以不变。
- 支持文字与附件一起修改，也支持只有附件的消息。
- 纯附件或只有空白正文的消息不显示复制文字按钮；含文字的消息复制完整正文，保留原有空格和换行。
- 编辑框显示原图片和新添加图片的缩略图；点击缩略图使用 DSH 原生图片预览放大，点击背景、关闭按钮或按 Esc 返回编辑，保留草稿和附件。预览读取或加载失败时，仍保留文件名和移除操作。
- 打开编辑、文字增高及增删附件时优先向上展开，取消时保持下方回答的位置；滚动空间不足时按可用空间调整，不覆盖上方消息。
- 多文件选择、拖入、粘贴；取消还原原内容。
- 原有和新添加的普通文件与文字位于同一编辑框，显示为 DSH 原生蓝色文件名标签，不附加删除 X。可在文件前、文件之间和文件后继续输入；选择文件后保留选文件前的光标位置，输入从新标签后继续，无需补空格。
- 普通文件标签可用 Backspace、Delete 或选中后剪切整项移除，撤销可恢复真实附件；发送时保留原附件引用或新文件内容，文件名不混入正文。
- 消息里由 DSH 识别的文件路径引用，打开编辑后仍显示蓝色文件名标签，可在前后输入文字或整项删除；提交和复制保留原始引用文本。没有可用的原生文件识别规则时保留普通文本，避免误识别或丢失内容。
- 移除附件**不删除电脑上的原文件**。
- Enter 直接发送，Shift+Enter 换行，Esc 取消；Ctrl/Cmd + Enter 仍可发送。中文输入法确认选字不会误发送，长按产生的重复按键不会重复提交。
- 纯文字、文字加附件、纯附件消息即使内容未改动，也可点击发送或按 Enter 重新生成，支持分支与当前对话两种模式。模型运行失败或成功结束后都可主动重发，无需修改文字或重新选择附件。
- 空消息、提交中、不可编辑时仍禁用发送。失败保留草稿；提交状态不确定时要求先刷新检查，避免重复运行。

使用 DSH 原生 SVG、主题颜色、字体和圆角。设置支持深色及窄窗口；保存失败时保留服务器已经接受的选项。设置读取失败会显示原因并提供「重试」，重新打开设置也会尝试恢复读取。服务未就绪或配置异常会单独提示，不再统一显示为会话尚未加载；读取到有效模式前仍禁止编辑，避免误用分支模式。

信息图标沿用 **DSH 原生提示框的样式和交互**，只显示「在当前对话重新生成」或「在新分支重新生成」，不附带说明段落。附件、模式及消息操作的短提示优先在对应按钮正下方居中，间距 8px。支持悬停、键盘聚焦；模式提示也可点击固定。详细规则保留在设置页面，模式在打开编辑框时固定。

较长的编辑限制说明位于按钮下方并与按钮右边对齐，不再推到整排时间和按钮的左侧。靠近窗口边缘时先水平调整，空间不足或挡住本消息内控件时再翻转；拥挤时保持提示可见并尽量减少遮挡。普通提示简化为「复制」「编辑」「添加附件」，完整无障碍标签保留；限制说明简化为「仅支持最近一条主消息；更早消息请使用分支模式」。

时间沿用原生规则：当天显示时分，其他日期带月日，跨年带年份，跨过午夜自动更新。悬停或用 Tab 聚焦时间可查看完整本地年月日和时分秒。鼠标复制后移开可收起工具栏，键盘复制保留焦点；复制失败仍显示错误。点击不可编辑的铅笔不追加重复文字；提交失败和结果不确定的提示会保留。

当前版本为 **0.3.0**。339 项自动回归、官方隔离 Web/Host 的离线验证、实际重启恢复及浏览器文件编辑验收已通过，发布前桌面实测也已确认通过。详细范围见 [验证记录](docs/VALIDATION.md)。

## 安装与升级

支持 **DSH 0.2.2-rc.1**，发布前桌面实测已确认通过。0.3.0 另在 Windows 的 **DSH 0.2.1-rc.5 官方 Web/Host** 中使用桌面安装包自带 CLI、独立配置与离线适配器验证，并完成真实 Host 重启后的会话恢复。rc.3 的 Web/Host 验证属于历史基线。真实外部模型、物理中文输入法、其他宿主版本和远程代理未纳入自动验收。

下载 [0.3.0 兼容性修订包](https://github.com/maxy1817/dsh-inline-edit/releases/tag/v0.3.0-compat.1)。包内版本仍为 0.3.0，修正 DSH 0.2.2-rc.1 和 schemastery 3.19.0 的依赖声明；旧版 0.3.0 安装包未包含此修正。同版本重装不会自动提示升级。

在安装包目录执行：

~~~powershell
dsh plugin --profile desktop add "./dsh-inline-edit-0.3.0-compat.tgz"
~~~

Web 配置把 desktop 改为 web。找不到 dsh 命令时，使用桌面安装目录下 resources/runtime/cli/bin/dsh.cmd 的完整路径。重新打开 DSH，在设置中选择模式。预构建包无需安装开发依赖。

升级可安装新包；如提示已存在，先在插件管理中卸载旧包，再安装。默认仍为分支模式，不会自动修改已有聊天。

~~~powershell
dsh plugin --profile desktop remove dsh-inline-edit
~~~

插件已收录到 [awesome-dsh-plugin 目录](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)。市场安装版本取决于目录中的安装包地址，更新合并并刷新索引后生效。尚未发布 npm，请使用 GitHub Release 附件或市场安装，见 [发布说明](docs/PUBLISHING.md)。

## 历史与边界

DSH 采用追加式日志。本插件使用公开 Session API 替换模型上下文，通过原生界面扩展过滤旧消息；**不改写或物理删除原日志**。旧内容可以在「轨迹」中审查，实际轮次和 Token 消耗继续保留。原生轮次导航仍以完整日志为准，可能包含已替换轮次。

停用插件后，原生聊天视图可能重显旧审计正文，但模型上下文仍采用已提交的替换；重新启用恢复过滤。不能将本功能视为隐私擦除。

**重新生成不会撤销已经执行的文件修改、命令、工具或外部操作。**

连续修改同一条消息时，旧版本的恢复记录也会退出活动上下文；从修改后的消息创建分支同样回退至其原始边界。编辑中断后如果已经出现新的用户输入，不再自动补发那次旧编辑。正常的更早对话继续保留。读取磁盘文件、轨迹或外部记忆的工具仍可能重新取得历史内容，本功能不清除这些外部状态。

其他限制：

- 已压缩且离开当前模型上下文的消息，不支持当前模式，请使用分支。
- 技能/会话引用、子智能体和非普通用户来源消息不重发，避免丢失语义。
- 最多 32 个附件；单个 64 MiB、合计 128 MiB、图片合计 20 MiB；仍受模型和 DSH 限制。
- 图片支持 PNG/JPEG/WebP/GIF；其他文件使用原生上传。文本最多 20 万字符。
- 草稿仅在内存，刷新、切换会话或关闭程序后不保证恢复。
- 同时替换聊天 Flow/消息槽位的第三方插件需额外兼容测试。

## 开发

以下命令仅适用于完整源码仓库，不适用于解压后的预构建分发包。需要 Node.js 24.9+：

~~~sh
npm ci
npm run check
npm pack
~~~

随源码提交预构建 lib/ 和 .gitattributes。后者保留 src/style.css 的 CRLF 换行，使文本加载器生成的 CSS 字符串在不同平台与现有构建包一致。React 与 Host API 使用宿主模块。无安装脚本，不全局安装、不修改 PATH。

Host 走 DSH 已认证的 Connection，不另开端口。附件只接受可信原消息引用或目标会话上传收据；不能提交任意磁盘路径。当前模式有空闲锁、尾序号检查、请求去重和中断恢复。模型收到简短编辑说明及新问题，不会收到被替换的旧问答。
